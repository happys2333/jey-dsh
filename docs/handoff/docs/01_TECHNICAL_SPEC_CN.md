## 0. 要实现什么

开发一个**嵌入现有 Agent 的、可替换模型的结构化决策层**。它不替代主模型的规划、生成、代码修改，也不接管宿主授权体系。它在明确节点判断：当前工具调用是否与任务一致、是否缺少关键证据、是否触犯已声明约束、工作流是否无进展、哪些工具更值得优先考虑。

第一版交付一个真实可安装的 DSH 插件、一个独立 MCP 服务、一个不依赖 DSH 的决策核心、一个真实本地推理服务以及官方 Jev 提供方。所有功能通过配置逐项开启。**没有任何模型密钥也能做工程测试；没有真实模型证据不能宣称 AI 功能合格。**

核心价值必须通过同任务对照证明，而不是通过代码量、测试数量、演示视频或者“高置信度”证明。收益目标是减少错误调用和无效重试；延迟、成本、误拦和完成率同时计入。

### 0.1 首版边界

| 范围 | v1 必须完成 | 明确不属于 v1 发布承诺 |
|---|---|---|
| 决策核心 | 强类型请求、逐问题结果、策略合并、超时、取消、审计 | 自主学习、自主改阈值、通用工作流平台 |
| DSH | 执行前评估、最终结果观察、生命周期、审批保持、原生测试 | 任意版本 DSH 兼容、恶意宿主插件隔离 |
| 工具路由 | 多标签相关性排序、建议、恢复入口 | 未验证时序前的动态工具硬隐藏 |
| 本地 | 至少一种真实模型后端、断外网验证、模型身份锁定 | 所有 GPU/系统等速、复刻 Jev 权重或训练 |
| 云端 | 官方 Jev 协议、显式外发授权、契约测试 | 无账号时凭空通过真实云端测试 |
| MCP | stdio、工具列表/调用、结构化输出、错误处理 | 自动拦截所有 MCP 宿主的其他工具 |
| 交付 | 构建产物、证据、安装/卸载、CI、授权后的上传 | 自动公开 npm 发布、向第三方仓库发 PR |

完整 v1 由“工程合格”和“至少一个真实提供方质量合格”组成。本地部署是本项目目标，因此**本地合格不能被云端合格替代**。云端接入功能可在缺少凭据时以“实现已完成，真实验证 BLOCKED”单独报告。

### 0.2 三条不可妥协的约束

1. **不增加权限。** AI 返回“没问题”只表示它没有提出额外限制，不能取消宿主 deny、ask、沙箱和资源权限。
2. **不伪造有效性。** Mock、回放、真实推理必须分开；跳过不能算通过；未知成本不能记为零；阈值不是安全证明。
3. **不静默外传。** 插件本地安装、shadow 模式、本地 HTTP 代理均不自动等于离线推理。严格本地模式不得回退云端。

## 1. 事实基线与对现有项目的判断

### 1.1 固定依赖，而非跟随 latest

本次核实 DSH 的 `master` 指向提交 `c36a83ff6bb95e3f82cf79f9be7c724270a8aa61`，发布提交标注版本 `0.1.7-alpha.1`。[S01]

本地 Agent 首先以此为兼容基线，实际安装后记录包版本、完整提交、Node/pnpm 版本、锁文件哈希。若源代码与已发布包的接口不一致，分别记录，不能混合源码接口和旧 npm 运行时。使用更新版本必须先补兼容性 ADR 并重新跑宿主合同测试。[S02]

SemIf 是独立本地研究实现，其 `master` 本次指向 `1f2dea3e25379f9dfc98cb83c324f00ab5deda37`。它不是 Jev 本体。上游代码许可证与模型许可证分别处理；本项目不分发权重。[S10]

### 1.2 不把“感觉写得不好”当成审计结论

对 `buberlo/dsh-jev` 的本次阅读是定向源码审查，不是完整安全审计。它已有独立核心、取消处理、模式切换和执行前适配；不能把这些说成不存在。我们选择独立实现，是为了明确契约、减少功能耦合、建立真实评测和本地后端，而不是简单改名。

以下是**需要通过测试确认的风险点**，不是已复现的故障：

| 编号 | 观察 | 要验证的影响 | 新实现要求 |
|---|---|---|---|
| R-01 | 上游 `pre-step.ts` 在 `agent/pre-step` 中改变工具 restriction；DSH 生命周期说明先 assembly，再 pre-step。[S03][S11] | 当前请求 schema 是否已旧、但执行可见性已新 | 在实际模型请求边界捕获 schema；未通过一致性测试不得开启硬筛选 |
| R-02 | 同文件先 `await next()`，提取任务却读取 payload 的 messages，而非返回决定里的 messages。[S11] | 其他插件改写输入后，决策看到的是否仍是旧输入 | 保存 authoritative decision 内容；加入多 listener 改写回归 |
| R-03 | 任务摘要采用最近用户消息并截断。[S11] | 多轮约束是否丢失，中文长输入是否被切断关键限制 | 独立约束记录，显式缺失状态；不能靠最后一条文本替代任务状态 |
| R-04 | 工具流水线具有可重排异步策略与最终同步 guard。[S04][S05] | 仅用 waterfall 合并能否覆盖全部受支持组合 | 硬拒绝进入单调 guard；审批要求做组合契约；不声称抵御恶意同进程插件 |

该项目本次固定参考提交为 `d2f77a1f68906d1576caaa8aa22be65913905d19`。不复制其业务核心；若借用具体实现需保留许可证，并标注来源。[S11]

### 1.3 DSH 的关键事实

宿主公开有 `tools/pre-execute`、`tools/result`、`ctx.tools.guard()`、`agent/pre-step`、`agent/request`、`system-prompt/assemble` 等扩展点。**guard 同步、只拒绝或不干预；`tools/result` 是最终冻结结果的同步通知，不是异步模型回调。** [S04][S05][S06]

工具 restriction 是作用域过滤，并非覆盖所有局部工具或保留传输工具的安全屏障；它改变可见性与分派条件，不应被误用为模型授权机制。[S05]

## 2. 设计原则与非目标

### 2.1 采用模块化单体，不采用微服务平台

TypeScript 核心在 DSH/MCP 进程内使用；只有模型推理放入独立 Python 进程。第一版不引入 Redis、Kafka、数据库集群、K8s、控制面、用户系统或远程仪表盘。JSONL、只读报告和有界内存足以完成验收。

这样既能复用核心，又不必在一个插件项目中承担分布式一致性和运维负担。后续出现真实跨进程共享需求，再讨论持久化。

### 2.2 让规则解决规则，让模型解决语义

路径限制、工具身份、预算、最大调用次数是代码规则；“是否符合任务”才是模型判断。对通用 shell 的真实副作用无法仅凭字符串准确判断，因此未知命令按宿主审批/沙箱处理，不声称用几个正则构造完备安全系统。

重复相同确定性错误，优先采用无进展计数，而非额外询问模型。模型不负责给自己授予权限，也不得调整预算、提供方、阈值或模式。

### 2.3 决策不是执行

核心返回观测值与建议。宿主适配器完成审批映射，执行始终走宿主已有 pipeline。禁止新增后门式 `child_process.exec()` 帮 Agent 绕过工具注册、日志、审批和沙箱。

本地推理服务只接收文本/结构化状态进行评分，不接收任意文件读取路径、任意命令或任意目标 URL。模型下载由独立 setup 步骤完成，不在一次决策中动态下载。

## 4. 领域模型与请求生命周期

### 4.1 独立的三类对象

**Observation（观测）**：模型确实返回了什么。  
**PolicyDecision（策略决定）**：代码如何解释观测。  
**ExecutionOutcome（执行结果）**：宿主实际执行或拒绝了什么。

三者分开记录。不允许把模型回答“通过”写成工具已成功执行；不允许把宿主拒绝写成模型预测正确。

### 4.2 核心请求

本项目边界类型见 `contracts/core-types.ts`。请求必须包含：版本、请求 ID、用途、快照标识、实际状态、问题、预算。取消信号属于同进程调用上下文，不序列化进 JSON。

快照至少绑定：

- 会话/agent/turn/step 标识、插件代次、政策版本；
- 当前任务摘要、仍生效的用户约束与来源引用；
- 当前调用的工具身份、冻结参数摘要和哈希；
- 相关的近期最终执行结果、工具目录摘要；
- 任务状态、证据是否充分、哪些信息被裁剪；
- 观测截止序号，而不是含糊的“最近上下文”。

约束摘要仅是模型输入；可执行的硬约束来自用户/管理员明确配置。摘要不能新增授权。缺少初始用户要求时应标记 unavailable，而非默认无约束。

### 4.3 逐问题状态

`answered` 表示通过结构校验且有真实输出；`abstained` 表示提供方或策略不能判断；`error` 表示传输/协议/运行故障。整个调用可以部分成功，但**必需的执行检查题缺失时不得当作通过**。

错误类别至少包括：`INVALID_INPUT`、`UNSUPPORTED_CAPABILITY`、`AUTH`、`RATE_LIMIT`、`OVERLOADED`、`TIMEOUT`、`CANCELLED`、`QUEUE_FULL`、`BUDGET_EXCEEDED`、`INVALID_RESPONSE`、`INSUFFICIENT_CONTEXT`、`STALE_SNAPSHOT`、`LOCAL_NOT_READY`、`EGRESS_DENIED`。

`OTHER/NONE` 是分类选项；`abstained` 是不能给出可信判断。两者不能混同。信息不足不必强行映射成 noul=0.5；它应另有 evidence-sufficient 观测或显式 abstention。

### 4.4 生命周期

```text
CREATED → SNAPSHOTTED → ADMITTED → QUEUED → RUNNING → OBSERVED
                                                   │
                          VALIDATED → POLICY_APPLIED → RECORDED
任何阶段 → CANCELLED / TIMED_OUT / FAILED / STALE → RECORDED
```

进入终态后不能重新写策略。结果只能应用一次；审计终态必须有唯一 `(session, requestId, generation)`。迟到回答可以增加诊断事件，不得覆盖已执行的动作。

## 5. 输入构造、上下文与隐私

### 5.1 来源分层

`trustedPolicy` 只容纳管理员/用户显式配置；`userTask` 为宿主承认的用户输入；`observations` 包含工具、文件、搜索结果，全部按不可信内容处理。来源标签有助于程序隔离，但**不能保证模型不会受提示注入影响**。

多轮用户要求不能仅保留最后一条。建立一个有限的 TaskEnvelope：初始目标、当前子目标、未撤销约束、最新修订与来源事件。若“不要改生产配置”仅存在于已经被压缩的历史，插件不得因为看不到它就放宽已有硬策略。

### 5.2 裁剪顺序

先保留固定规则和本次调用，再保留相关最终结果，最后取近期对话。禁止简单 `text.slice(0,N)` 后不告知截断。限制要以 UTF-8 字节及实际 tokenizer token 为口径；无法可靠计算 token 时记录字节限制，不冒充精确 token。

按 JSON 字段边界裁剪；过长单值标注 omission 与原长度；不截断 JSON 生成非法负载。关键政策或调用参数无法容纳时直接 `INSUFFICIENT_CONTEXT`，不可静默丢掉后继续给出强判断。

### 5.3 外发策略

默认 `egress.mode=deny`，不建立提供方网络连接。使用本地服务须显式改为 `local-only` 并限定 origin；云端须显式改为 `allowlist`（详见协议附录）。允许云端时需同时具备：显式提供方选择、有效凭据引用、端点白名单、用途允许列表和数据字段允许列表。Shadow 也遵守这些条件。

严格本地模式只允许本项目受控的本地评分服务。单凭 URL 是 localhost 不能证明后端未代理云端；`local-qualified` 还要求后端代码审查和 OS/容器层断外网测试，模型及 tokenizer 均从本地预置。

禁止让模型参数指定 endpoint、header、密钥、模型路径或插件配置。HTTP 禁止自动跟随重定向；禁止将云端 Bearer 凭据传给其他 origin；本地服务绑定 loopback，使用独立随机 token，不开放 CORS 到任意网站。OS 用户权限与防火墙是最终边界。

### 5.4 审计数据分层

默认公共日志只记录 ID、原因码、模型标识、耗时、状态、计数；不记录原始参数和完整上下文。审计用不可枚举随机 ID；低熵敏感文本不要直接公开 SHA-256 以免字典猜测。必要时在本地使用带密钥摘要，密钥不进入证据包。

可选私有 replay 数据必须显式启用、本地访问受限并设置保留期。模型可见的插件提示仍通过 DSH 支持的持久化路径记录。**只有摘要的日志可复核决策过程，不足以重新推理；不能把它宣传成完整可重放。**

## 6. 提供方设计

### 6.1 官方 Jev

官方端点为 `POST https://api.typesafe.ai/v1/systemone`；请求含 `state`、`model`、`questions`。Choice 选择候选项，Noul 返回“是”的概率，Score 返回有序等级上的加权值。[S07][S08]

适配器必须核对响应题 ID、类型、候选键、有限数值、范围、总和与选择一致性。不要用 `response.json() as Answer` 跳过边界验证。Choice 与 Score 可以保留 provider 原始 confidence；Noul 没有独立 confidence 字段。[S09]

使用具体模型版本进行评测；允许安装时使用别名，但记录服务返回的实际 model，并在版本变化时使旧校准与缓存失效。供应商未给出费用字段时记 `null` 或明确估计值，不能将 output token 不收费与 output token 数量为零混淆。

重试仅由一层负责：本项目协调器或已配置 SDK 二选一，避免 SDK×核心×HTTP 的重试乘法。认证/结构错误不重试；限流/过载在剩余 deadline 和费用预算内退避；即使服务不收费，重复请求计数也不能消失。[S08]

### 6.2 本地模型：SemIf bridge

本项目新增 Python 常驻服务包装固定版本 SemIf，不宣称 SemIf 原生提供本项目 HTTP API。上游已有直接候选评分及 CPU/GGUF、CUDA 和 Apple 平台的实现路径，具体当前可用性以固定提交能力探测为准。[S10]

首选实作顺序：CPU/GGUF 最小端到端或已有 NVIDIA GPU 的 direct scorer → 常驻模型 → 生命周期与离线验证 → 缓存/批处理。不要每次请求启动 Python CLI 并重新载入权重。开发阶段可以用上游 CLI 验证原始输入/输出，但不把 CLI 每次冷启动作为生产架构。

本地 RPC 为本项目定义，默认端点例 `http://127.0.0.1:17861`，端口可配置。服务暴露 `/health/live`、`/health/ready`、`/v1/capabilities`、`/v1/decide`。ready 仅在模型、tokenizer、模板和后端完成检查时返回可用。

`capabilities` 必须报告：scorer 版本、模型 revision、权重摘要、tokenizer revision、量化、模板 hash、平台、可处理的题型、最大上下文、是否支持协作取消、概率来源。健康检查不能触发下载。

### 6.3 本地概率的语义

直接 logit 路线对候选标签计算 `p_i = exp(z_i/T) / Σ exp(z_j/T)`，这是**给定候选集合下的条件分布**。本项目定义该公式，不能推断它复现 Jev 架构。

要求验证标签在实际模板/tokenizer 下的编码；一个标签不止一个 token 时，不可只读取第一 token 还宣称完整选项概率。优先使用已经验证的上游评分方式；新模型必须有 tokenizer 对齐测试、选项换序测试、中英文测试和“无候选适合”的测试。

相关工具是多标签任务。对每个候选独立提出二元相关性问题，或以清晰 rubric 评分；**不能把一次 Choice 的互斥分布直接当成多个工具各自相关概率**。Score 的等级索引和归一化值分开保存，不能默认为 0～1。

### 6.4 校准

只在独立校准集上拟合温度/阈值。保存模型、模板、量化、任务和数据版本；任何一个变化都需要校准适用性重验。没有校准文件时标注 `uncalibrated`，不编造 confidence。

提供方 confidence、选中项概率、校准后的概率是不同字段。即使校准通过，也不将单个分数解释为动作安全保证。不建议首版学习路由阈值或在线自学习。

### 6.5 Mock

Mock 只用于单元、属性和宿主故障注入测试；每次输出 `synthetic=true`，外层报告必须标记。生产配置禁止使用 Mock 加 `enforce`，测试专用入口除外。提供方缺失时报错，不偷偷切换 Mock。

## 7. 执行前语义检查

### 7.1 三类问题

对需评估的具体工具调用，一次批量询问：

1. 本次调用是否推进当前用户目标？
2. 判断/执行所需的关键事实是否充分？
3. 本次调用是否与列出的明确限制冲突？

每题单一语义，说明“只能根据给定证据”。问题模板版本化。执行检查不使用模型生成的长篇理由作为程序条件；模型观测之外的解释由程序以稳定原因码和证据引用生成。

### 7.2 纯策略

本项目插件动作只有 `abstain`、`ask`、`deny`、`cancel`。**没有“无条件 allow”动作**。

| 宿主原决定 | ADL abstain | ADL ask | ADL deny | ADL cancel |
|---|---|---|---|---|
| allow | 保留 | ask | deny | cancel |
| ask | 保留 ask | 保留 ask，合并审计原因 | deny | cancel |
| deny | 保留 deny | 保留 deny | 保留 deny | 保留 deny |
| cancel | 保留 cancel | 保留 cancel | 保留 cancel | 保留 cancel |

用户取消优先于模型建议。`ask` 是否获批完全由宿主处理；没有审批渠道时不执行。询问只针对当前冻结调用，不给后续相似调用重复使用授权。

不同性质的失败不能统一处理：

| 失败位置 | v1 行为 |
|---|---|
| 工具推荐失败 | 不应用推荐，保留宿主原能力 |
| shadow 评估失败 | 记录失败，不影响原执行 |
| enforce 必需语义检查失败/不充分 | ask；无人值守无审批则拒绝 |
| 硬规则冲突 | deny，不调用模型 |
| 用户取消 | cancel，并取消关联推理 |
| 过期快照 | 作废观测；保护功能按检查失败处理 |
| 观测报告失败 | 尽量保留执行；若配置强制审计则在 dispatch 前失败关闭 |

阈值在 calibration 工件中配置。初始无真实校准时不启用“按概率自动拒绝所有调用”；可先 shadow、提示或请求审批。硬规则始终可以拒绝。

### 7.3 DSH 的两层机制

异步 `tools/pre-execute` 进行模型调用和宿主决定合并；同步 `ctx.tools.guard()` 只读取已经存在的硬规则/确定性拒绝证据，绝不调用网络。[S04][S05]

对一次受保护调用，证据以 registry 分配的 execution token 关联，不能只用工具名或会话 ID。token 是运行时身份，不序列化到磁盘。同步 guard 不应尝试在 Promise 未完成时“等待模型”。

**边界说明：** 本插件自己的代码不会放宽下游 ask/deny；最终 guard 能加不可被普通 waterfall 放行覆盖的拒绝。但本项目不能保证任意恶意同进程插件不篡改其他状态或直接执行代码。也不能在没有宿主审批证明接口时声称最终 guard 可以识别一切被其他 listener 改写掉的 ask。M0 必须固定受支持插件组合，测试 ask 的端到端效果；若组合会丢失必需审批，拒绝该组合的 enforce 模式。

## 8. 工具路由与模型路由

### 8.1 v1：相关性建议，不改变权限

输出每个候选的相关性与证据充足程度，保留 `noneApplicable` 和基础恢复能力。候选集从宿主当前可见工具中获取，不从全局注册表恢复已被其他策略隐藏的工具。局部工具、同名 shadow、传输工具分别识别。

相关性建议只进入下一次适当模型上下文；限制每个 step/任务版本最多一条，禁止通过连续 inject 使 Agent 永不结束。预算不足、上下文不完整或目录变化时不应用建议。

### 8.2 可选能力：presentation-only 筛选

这是 v1 的可选增强，需要单独 gate，不是自动权限收缩。只能在 DSH 支持的 `system-prompt/assemble` 路径中返回当前 assembly 的工具子集；不在 pre-step 之后盲目调用 restriction。对初始任务未被承认、消息将被改写或快照不充分的情况，保留完整的原可见工具集合。[S03][S06]

必须验证：实际发往模型的工具 schema、request 日志、候选计算、恢复入口一致。未通过 gate 时维持建议模式，不能假称“已自动减少当前请求的工具 token”。

该筛选不承担授权职责。对宿主可执行性有任何改变必须有独立适配规范。保留显式扩展工具集合的入口，只能恢复本插件隐藏的部分，不能扩大其他策略权限。移除本插件自身 lease 必须与读取候选集处于不可交错的同步片段；绝不在去除限制后 `await` 留下临时权限窗口。

### 8.3 模型路由在 v1 默认关闭

定义接口但不以“全自动切换所有模型”作为发布门槛。后续实现需在 `agent/request`/实际 prepareCall 绑定前，按允许的 route ID 选择；检查工具调用、图像、上下文长度、结构输出与凭据能力。候选不满足任务所需能力时不得切换。[S02]

同一 step 的网络重试不重复随机选路；记录本次请求实际模型，不把模型切换产生的额外前缀缓存损失隐藏在成本里。没有实测收益就继续使用宿主原路由。

## 9. 无进展检测与结果观察

`tools/result` 回调只做有界同步更新和排队，返回后由拥有生命周期的 worker 处理非关键统计；禁止在该同步事件中直接 `await` 模型。宿主最终结果到达后，再记录成功/失败，不根据中间 post 结果计数。[S04][S05]

指纹由工具 ID、规范化参数、可识别的确定性错误、相关资源版本和目标版本组成。成功调用、参数实质修正、观察到资源变化应重置计数。状态轮询是特殊类别，有独立 poll budget；不能把重复 `get_job_status` 当作卡死。

设 `maxIdenticalFailures=3` 仅是初始可调示例，不是普适常数。第 1～2 次允许 Agent 修正，达到限制时暂停同一路径并给出可恢复的错误；不能永久封禁整个 Agent，也不自动终止用户任务。工具输出的“我已修复”文本不能单独作为进展证据。

PTC/嵌套调用以 rootCallId 和 parent token 归组。子调用与外层结果不能重复计入一次失败；外层取消不能把已完成子调用的副作用从报告中抹掉。

## 10. 并发、取消、超时、缓存和预算

### 10.1 快照有效性

每次推理绑定 `(agent, generation, policyVersion, taskVersion, callDigest, catalogDigest)`。应用前重新验证。判断过程中用户修改限制、插件重载、工具更换 schema 或调用已取消，旧结果一律失效。

不要用整个全局 `tools/change` 的单一计数器作为全部 agent 的语义版本：该事件包括本插件 restriction 变化，易造成自我失效或无关 agent 相互干扰。[S05] 需要重新计算当前 scope 的有效目录摘要，并单独跟踪本插件 lease。

版本检查与动作发布之间不能再有 `await`。但这仍不能锁住外部文件系统/网络状态；对真正的 TOCTOU 风险，最终执行工具应验证资源版本，敏感操作走宿主 sandbox/权限控制。

### 10.2 队列与取消

每个提供方有并发上限、有界队列与每会话公平性。截止时限包含排队时间；排队超时不应消耗模型额度。用户 abort、插件 dispose、deadline 均传递到提供方。禁止只有 Promise.race 而底层计算永不停止。

本地 GPU 计算未必能中断内核。先标记结果废弃，worker 在安全点回收；需要硬超时时由独立 worker 进程终止并重新就绪，不尝试在 DSH 主进程里强杀线程。硬杀后的模型重载计入运行成本。

关闭顺序：停止入队 → abort 在途 → 等待受限 drain → 关闭连接/worker → 移除本插件资源。不能误关外部用户管理的本地服务。

### 10.3 缓存

v1 默认不缓存执行前“通过”结论；只可缓存纯推荐或同一批重复问题。缓存键包含提供方、实际模型版本、模板、全部状态摘要、问题/选项顺序、校准和政策版本。禁止跨用户、跨 workspace 共享。

缓存是优化而非授权。命中也重验身份和 deadline。不缓存错误、用户审批和缺失信息的默认通过。推理缓存与 SemIf 内部 prefix cache 是两层；共享 state 必须字节/模板身份一致。

### 10.4 预算

按 turn、session 和 provider 设置请求数、最大状态、最大题数、排队上限和总耗时。没有准确费用数据时使用调用数/字节上限，不靠猜测美元账单。配额检查必须在并发安全的 reservation 阶段完成；完成后结算实际用量。

默认离线，不产生云端账单。云端 live 必须由用户明确给出测试预算；没有预算就继续其他测试并标记 live gate BLOCKED。

## 11. 审计、持久化与可观测性

每次决策记录固定 schema：请求/会话/调用 ID、provider 类型、synthetic、实际模型、模板、快照引用、三段耗时（queue/inference/total）、逐题状态、策略动作、宿主原决定、最终执行结果、失败码、是否外发、是否过期。

DSH 模型可见的内容必须通过宿主持久事件/受支持 context 路径进入记录，不能悄悄修改将发送的 messages。针对现有内容投影也必须使用官方支持的机制。[S02]

本地诊断 JSONL 是单写者追加、有界轮转；进程崩溃后允许最后一行不完整，恢复器隔离该行而不改写已确认事件。不要使用虚假的“绝对不可篡改日志”表述：普通文件与哈希只能辅助一致性校验。

开发版提供只读 `status/doctor` 命令，输出模式、提供方、实际推理状态、兼容版本、外发策略、功能 gates、最近错误和计数。凭据只显示“已配置/未配置”，不显示值或完整环境。

最小展示无需复杂 Web 前端：DSH 通用工具卡、结构化日志和静态报告即可。UI 明确区分 MOCK / LOCAL / CLOUD、SHADOW / ENFORCE，不能显示绿色“安全保证”。

## 12. MCP 适配

v1 只提供三个工具：`adl_choose`（互斥选择）、`adl_check`（根据明确证据判断）、`adl_rank`（独立评分/相关性排序）。禁止提供 `adl_execute` 或 `adl_set_policy`。

MCP 的 `inputSchema`、`outputSchema` 与核心契约同源生成；输出 `structuredContent`，并提供兼容文本 JSON。工具执行错误与 JSON-RPC 协议错误分开。模型输入可以定义判断问题，但不能伪装 host-attested call 做审批，也不能替换固定语义 gate 模板。[S12]

stdio 的 stdout 仅含协议消息，日志写 stderr。命令启动时配置文件和环境决定提供方，不按“发现某个 API key”偷偷切换云端。MCP 工具调用也要执行外发限制和额度检查。

MCP 是能力暴露，不是对所有 Agent 的透明拦截。Claude Code/OpenCode 等原生 hooks 适配是后续独立任务；不把 MCP 工具测试当成这些宿主自动接入已完成。

## 13. 配置与部署

配套 `templates/adl.config.example.json` 是本项目配置设计，不是现成 DSH 上游字段。Agent 需实现校验 schema、默认值与文档同步测试。

启动时检查自相矛盾配置：非 off 模式未选 provider、Mock enforce、local+云回退、开启审批功能但无对应宿主能力、超时/队列非法、未知字段均应明确失败。能力缺失不能静默安装成功但功能无效。

**默认推荐：** `mode=off`，所有自动功能关闭，provider 未就绪；doctor 清晰说明怎样启用。开发 smoke 显式指定 Mock+shadow。完成本地模型验证后设为 local+shadow；通过质量门槛再由用户启用 enforce。

本地服务由独立命令启动。DSH 插件既可连接用户已启动服务，也可在显式 managed 模式下启动受控 worker；两种 ownership 不混同。首版实现 external 模式即可，但提供可靠 readiness、重连和 shutdown 行为。

Windows 原生、WSL2、Linux、macOS 是不同运行环境，报告分别列出。优先用户当前平台加 Linux CI，不宣称仅在 WSL 测试等同 Windows 原生通过。

## 14. 测试、质量与性能验收

详见测试规格。关键区别：

- **工程验证：** 在真实 DSH 加载构建产物，用可控模型驱动器走完整 lifecycle，证明钩子、审批、取消、日志、安装正确。
- **真实推理验证：** 真正加载本地权重或真实 Jev API，验证输出、耗时、模型身份和失败模式。
- **系统收益验证：** 同任务对照，既测失败率，也测实际完成和成本。

不能用回放证明新策略下 Agent 重新规划的完成率，也不能用一张演示图证明稳定性。回放只证明固定轨迹下 gate 的反事实反应。

所有性能数字均需硬件、模型、输入长度、题数、并发、冷/热缓存和测量边界。首版硬目标是工程正确；延迟目标是待验证 SLO，不引用供应商宣传值作为本地实测。

若真实模型质量达不到标准，仍交付工程产物和失败报告，但保留 shadow/建议模式，不发布“质量合格”声明。不能通过删除困难数据、调测试集阈值或改比较基线让报告变绿。

## 15. 开发顺序与发布判定

顺序为 M0 兼容探针 → M1 核心契约/策略 → M2 DSH 原生闭环 → M3 提供方 → M4 MCP → M5 安全/并发 → M6 真实评测 → M7 打包/CI → M8 授权上传。

依赖未确认前不并行猜 API。M0 必須生成 `docs/HOST_CONTRACT.md`：上游确切 import、事件参数、生命周期顺序、安装方式、最小 smoke 结果。所有后续代码以它为依据；若与本设计有差异，先做 ADR，不得用 `any` 或禁用 TS 检查掩盖。

上传不是发布质量证明；工程通过不是本地模型合格；失败报告上传成功不等于项目所有功能通过。最终报告使用独立状态矩阵，不给模糊的一句话“全部完成”。
